# self-stream-kit

**OBS StudioとMediaMTXを使って、Windows PCに自分専用の配信環境を構築するための自鯖配信キットです。**

## self-stream-kitとは

普段の配信操作には**OBS Studio**、映像を受け取って配信するサーバーには**MediaMTX**、視聴ページやコメントなどの機能には**Node.js**を利用します。

外部の配信サービスだけに頼らず、自分で管理できるストリーミング環境をWindows上に用意したい人向けのプロジェクトです。

```text
┌────────────────┐       映像を送信       ┌────────────────┐
│   OBS Studio   │ ─────────────────────▶ │    MediaMTX    │
│   配信・録画    │                        │  映像サーバー   │
└────────────────┘                        └───────┬────────┘
                                                │ HLS
                                                ▼
                                      ┌────────────────────┐
                                      │  self-stream-kit   │
                                      │  視聴・コメント管理 │
                                      └─────────┬──────────┘
                                                │
                                                ▼
                                      ┌────────────────────┐
                                      │       ブラウザ       │
                                      └────────────────────┘
```

## 特長

- **Windows向け** — Windows PCでの利用を想定しています。
- **OBS Studioを利用** — 使い慣れたOBSの画面から配信と録画を行えます。
- **MediaMTXを利用** — 軽量なストリーミングサーバーで映像を扱います。
- **自分で管理** — 配信環境を自分のPCとネットワーク上に用意できます。
- **コメント・リアクション** — コメント、そうだね、画像・動画・音声リアクション、落書きを利用できます。
- **アンケート・ピン止め** — コメント欄上部でアンケートとピン止めコメントを同時に表示できます。
- **アーカイブ対応** — 配信録画と、その配信中のコメントを関連付けて表示できます。
- **複数画質に対応** — 入力コーデックと利用環境に応じて、高画質、互換高画質、低画質を扱えます。
- **安全な更新とロールバック** — 利用者データを保持したまま更新し、問題があれば更新前へ戻せます。
- **Cloudflare Tunnelは任意** — LAN内だけで利用することも、設定してインターネットへ公開することもできます。

## はじめ方

1. [最新リリース](https://github.com/ginsabo/self-stream-kit/releases/latest)を開きます。
2. リリースページから最新版の配布用キットをダウンロードします。
3. 同梱されている導入ガイドを確認します。
4. Node.jsとMediaMTXを用意し、`0_初回セットアップ.bat`を実行します。
5. `1_配信をはじめる.bat`を実行します。
6. 表示された接続情報をOBS Studioへ設定して配信を開始します。

> [!IMPORTANT]
> インターネット経由で公開する場合は、認証、ファイアウォール、ルーター、Cloudflare Tunnelなどの設定を確認してください。
>
> 意図しない第三者からアクセスされないよう、公開範囲は利用者自身の責任で適切に管理してください。
>
> Discord Webhook URL、管理パスワード、秘密設定、Cloudflareの認証情報などを、ログ、スクリーンショット、Issueへ掲載しないでください。

## 2026-08-07 更新内容

2026-08-05版で確認された、視聴画面の表示崩れと更新処理の不具合を修正しました。

### ピン止めコメント表示時に入力欄が隠れる問題を修正しました

ピン止めされたコメントの「全文」を押すと本文が上限なく伸び、コメント入力欄が画面の外へ押し出されて書き込めなくなることがありました。アンケートと同時に表示されている場合は、「全文／折り畳む」「元へ」の操作ボタンごと見えなくなるケースもありました。

- チャット上部の固定表示エリアに高さの上限と内部スクロールを設けました。
- 視聴ページと別窓チャットで同じ表示制御を使うようにしました。
- スマートフォンの固定入力欄と、幅の狭い別窓チャットでも、名前・コメント・送信操作が表示範囲内に収まるようにしました。

### コメント文字数の上限が反映されていなかった問題を修正しました

管理画面でコメントの最大文字数を変更しても視聴画面には反映されず、上限を超えた分は警告なく切り捨てられていました。

- 設定した上限を視聴ページと別窓チャットの入力欄へ反映するようにしました。
- 上限を超えたコメントは、無言で切り捨てず、理由を表示して送信を拒否するようにしました（HTTP・WebSocketの両方）。

### 更新が途中で止まる不具合を複数修正しました

環境によって、更新処理が途中で中止され、自動的に更新前の状態へ戻ってしまう問題がありました。

- OBSプロファイルのフォルダーが無い環境で更新が失敗する問題を修正しました。既存の配信環境にあるOBSプロファイルは、削除・一部削除・独自の内容に変更していても更新の妨げになりません（新規ダウンロード時の同梱プロファイルは、これまでどおり全件確認します）。
- `scripts`フォルダーに利用者が自分で追加したファイルがあると更新できない問題を修正しました。
- 導入先に利用者が追加したJS・CSS・独自テストがあると更新できない問題を修正しました。
- 特定の文字コードで生成された管理ファイルにより、配布直後だけ更新が失敗する問題を修正しました。

### 更新の実行結果が文字化けする問題を修正しました

`APPLY_UPDATE.ps1`・`ROLLBACK_UPDATE.ps1`をPowerShellから直接実行した場合に、日本語の実行結果が文字化けして読めないことがありました。`更新する.bat`・`もとに戻す.bat`からの実行と同じように、文字コードを初期化してから処理するよう修正しました。

### OBSプロファイルの取り扱いを明確にしました

更新手順書に「OBSプロファイルも自動で入れ替わる」と誤って書かれていました。実際には自動コピーされません。更新用ZIPに同梱しているプロファイルは、OBSへ手動で取り込んでください。

### 配布内容の確認を強化しました

- 視聴ページ・管理画面・別窓チャットなど、公開している全画面が同じ版の部品を読み込んでいるかを確認するテストを追加しました。一部の画面だけ古い部品が残る事態を防ぎます。
- 配布内容の一覧表を、配布用・更新用・更新キットの3種類すべてのZIPへ対応させ、相互に照合するようにしました。
- 配布後のテストが、検証用の控えではなく、実際にインストールされた起動bat・説明書・OBSプロファイルそのものを確認するようにしました。
- 前回リリースと今回リリースの配布内容を自動で比較し、廃止したファイルが退役リストへ正しく分類されているかを確認するようにしました。以前は手作業でリストを維持しており、追記漏れが更新失敗の原因になっていました。

### 内部整理

- 使われていない管理画面用のCSSを削除しました。
- アーカイブ画面で発生していたID重複を解消しました。
- 視聴ページと別窓チャットで重複していた入力欄の処理を、共通の部品へまとめました。
- CSSのインデントを統一しました。

2026-08-04版で確認された起動・更新不具合と、安全性・操作性の問題を修正しました。

### ランチャーがMediaMTX起動前に停止する問題を修正しました

2026-08-04版では、ランチャーが次のPowerShell関数を見つけられず、MediaMTXを起動する前に停止する場合がありました。


`mediamtx.yml`が壊れていない場合に、ランチャー側の実装漏れで設定エラーと表示される問題も解消しました。

### 初回セットアップと更新がアクセス権エラーで停止する問題を修正しました

Windowsが同じアクセス権を継承情報だけ正規化した場合でも、次のエラーとして扱われることがありました。

```text
MediaMTX config access control changed
```

実際のアクセス権変更と、Windowsによる安全な正規化を区別するよう修正しました。

MediaMTX設定の原子的置換や復旧に失敗した場合も、元の設定内容、ファイル属性、アクセス権を一組として復元・検証します。

所有者や監査ACLを勝手に変更することはありません。

### ピン止め機能の場所を分かりやすくしました

管理画面の項目名を、次のように変更しました。

```text
最近のコメント・通報・ピン止め
```

この項目は管理画面の「視聴者」タブにあります。

- 現在の配信セッションに投稿されたコメントだけをピン止めできます。
- 配信停止中はピン止めボタンを表示しません。
- ピン止めできない場合は理由を表示します。
- 削除・通報されたコメントは固定できません。
- 現在のピン止め状態を常時確認できます。

### 管理画面の項目を折り畳めるようにしました

管理画面の各カードへ、共通の折り畳み操作を追加しました。

```text
▼ 展開中
▶ 折り畳み中
```

- 項目名をクリックして開閉できます。
- 折り畳んでも入力内容や設定値は維持されます。
- 項目が増えたタブでも、必要な場所へ移動しやすくなりました。
- キーボード操作と`aria-expanded`にも対応しています。

### アーカイブコメントAPIの公開範囲を修正しました

公開アーカイブが存在しない配信セッションのコメントを、セッションIDだけで取得できる問題を修正しました。

- 公開されているアーカイブと関連付いているコメントだけを返します。
- アーカイブを削除すると、対応するコメントAPIも公開されなくなります。
- 過去ログ自体は削除しません。
- 管理者向けの保存データはそのまま維持します。

### 管理パスワード消失時の動作を安全にしました

インストール済み環境で、秘密設定と旧パスワードファイルが両方失われた場合に、既知の初期パスワードへ戻る動作を廃止しました。

パスワード情報が破損・消失している場合は安全停止し、復旧方法を表示します。

既存の管理パスワードが正常に保存されている環境では変更されません。

### 配信セッションの集計を修正しました

完了済みの配信セッションへ後から通報を記録した場合に、リアクション件数だけが再構築後の集計から抜ける問題を修正しました。

### コメジェネ連携を非同期化しました

- 待ち行列は最大256件に制限し、無制限にメモリを消費しないようにしています。
- 書き込み失敗時もプロセス全体を停止しません。

- `.log`、`.zip`、`.bak`、一時ファイルを共通の規則で除外します。
- 利用者の設定、秘密情報、ログ、素材、アーカイブを配布ZIPへ含めません。

## 2026-08-04 追加機能

### コメントを配信ごとに区切るようにしました

前回の配信コメントが次の配信にも残り続けないよう、コメントを「1回の配信」単位で管理します。

- 新しい配信を始めると、通常のコメント欄は空の状態から始まります。
- 過去のコメントログは削除せず、そのまま保存します。
- 30秒以内の瞬断やNode.jsの再起動では、同じ配信として復元します。
- 30秒を超えて停止したあと再開すると、新しい配信として扱います。
- 配信停止中に書かれたコメントは、次の配信へ持ち越しません。

### アーカイブに、その配信のコメントを表示できるようになりました

録画の時刻から対応する配信を特定できる場合、その配信中のコメントをアーカイブ画面へ表示します。

自動で判定できない録画は、録画ファイルの隣にあるJSONへ配信セッションIDを指定して手動で関連付けられます。

古い録画や古いコメントは削除せず、関連付けなしの状態で保持します。

### Discord通知で`@everyone`と`@here`を使えるようになりました

管理画面に、Discord通知の全員メンションを許可する設定を追加しました。

- 初期設定はOFFです。
- ONにしても、通知文に実際に`@everyone`または`@here`が書かれている場合だけ反応します。
- ユーザーやロールへの任意メンションは許可しません。
- Discord側で全員メンションを使用できる権限も必要です。

### MediaMTXを差し替えたあとの復旧を改善しました

MediaMTXのバージョンを差し替えたあと、HEVCや互換高画質などの選択肢が消え、元へ戻しても復旧しない場合がありました。

配信開始時に`mediamtx.yml`を再確認し、不足している安全な設定だけをバックアップ付きで修復します。

- 推奨バージョンは引き続き**v1.19.1**です。
- それ以外のバージョンでは警告を表示します。
- バージョン番号だけを理由に画質を非表示にしません。
- Control APIが復旧すると、更新BATを再実行しなくても画質状態を再判定します。
- 修復前の設定は`mediamtx\self-stream-config-backups`へ保存します。
- 未確認バージョンを正式対応として扱うものではありません。

### コメントのピン止め機能を追加しました

管理者が、現在の配信中のコメントを1件だけチャット上部へ固定できます。

- ピン止めと解除は管理者だけが行えます。
- 削除・通報されたコメントは自動で解除されます。
- 配信終了時に解除され、次の配信へ持ち越しません。
- Node.jsを再起動しても、同じ配信中であればピン止めを復元します。
- 投稿者名、本文、投稿時刻を表示します。
- 元のコメントは通常コメント欄に残ります。

### アンケートとピン止めが重ならないようにしました

チャット上部を共通の固定表示エリアに変更しました。

表示順：

1. アンケート
2. ピン止めコメント
3. 通常コメント

PC、スマートフォン、別窓表示でも縦に並び、互いに重なりません。

### そのほかの修正

- Node.js再起動時のコメントログと集計の復元処理を改善しました。
- 一部だけ書き込まれたログは、欠けた処理だけを再開するよう修正しました。
- 配布元の診断BATを、Windowsで安定して読めるCRLF・UTF-8 BOMなしへ修正しました。
- 不要になったAPIや重複していた処理を整理しました。

## 2026-07-30版・2026-08-04版・2026-08-05版からの更新方法

2026-07-30版、2026-08-04版、または2026-08-05版を利用している場合は、更新用キットを使用できます。

1. 配信を停止します（`2_配信をとめる.bat`）。
2. 「自鯖配信キット_更新」フォルダーを、現在使用している配信キットのフォルダー内へ置きます。
3. `更新する.bat`を実行します。
4. 数分かかるため、処理中は窓を閉じないでください。
5. 「Update completed」と表示されたら完了です。
6. `1_配信をはじめる.bat`から起動します。

更新時に保持されるもの：

- 管理パスワード
- 配信設定
- Cloudflare設定
- Discord設定
- コメントログ
- セッションログ
- リアクション素材
- 待機画面
- アーカイブ
- 利用者独自画像
- `mediamtx.exe`
- 既存の`mediamtx.yml`
- OBSプロファイル（利用者が追加・変更・削除している場合、その状態のまま維持されます）

更新前のファイルは`self_stream_update_backups`へ保存されます。

更新がうまくいかない場合は、`もとに戻す.bat`を実行すると、最新の更新バックアップを自動で選択して更新前の状態へ戻します。

> [!IMPORTANT]
> 更新中にエラーが表示された場合は、同じ更新を何度も重ねて実行する前に、表示されたエラーとログを保存してください。
>
> `mediamtx.yml`、設定、秘密ファイル、アーカイブ、コメントログを手動で削除しないでください。

## フィードバック

目的に合わせて、2つの窓口を利用できます。

### 匿名ご意見ボックス

「少し気になった」「こんな機能がほしい」など、気軽に伝えたい場合は[匿名ご意見ボックス](https://box.hat-work.com)をご利用ください。

GitHubアカウントは必要ありません。

### GitHub Issues

再現手順がある不具合、ログを使った調査が必要な問題、具体的な改善提案は[GitHub Issues](https://github.com/ginsabo/self-stream-kit/issues)をご利用ください。

不具合を報告する場合は、可能な範囲で次の情報を記載してください。

- 利用しているself-stream-kitのバージョン
- Windows、OBS Studio、MediaMTX、ブラウザのバージョン
- 問題が起きるまでの操作手順
- 表示されたエラー
- 再現するかどうか
- Cloudflare Tunnelを使用しているか
- H.264またはHEVCのどちらを使用しているか
- 高画質、互換高画質、低画質のどれで発生したか

Webhook URL、管理パスワード、Cookie、秘密設定、生IP、Cloudflareの認証情報などは掲載しないでください。
